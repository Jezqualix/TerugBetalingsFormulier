Technische verwachtingen:
- Maak een moderne webapp met frontend + backend.
- De frontend moet het formulier tonen.
- De backend moet validatie, opslag, uploadverwerking, mail en export afhandelen.
- Code moet proper gestructureerd zijn en klaar voor lokaal gebruik en deployment.

Functionele eisen:
- Formulier op basis van de screenshot.
- Verplichte en optionele velden duidelijk onderscheiden.
- Server-side validatie verplicht.
- Client-side validatie als extra, maar nooit als enige bescherming.
- Bestandsupload moet mogelijk zijn.
- Uploadlimiet: maximaal 2 MB per bestand.
- Beperk toegelaten bestandstypes expliciet en veilig.
- Bestandsnaam moet veilig verwerkt worden.
- Data opslaan in database via configuratie uit .env.local.
- SMTP mail verzenden na submit (bijvoorbeeld bevestiging naar gebruiker en/of notificatie naar beheerder).
- Voorzie export van submissions, bij voorkeur CSV en indien haalbaar XLSX.
- Voorzie een overzichtelijke admin/exportflow.

Beveiligingseisen:
- Bescherm tegen SQL injection.
- Bescherm tegen XSS.
- Bescherm tegen command injection.
- Bescherm tegen path traversal bij uploads.
- Sanitize en valideer alle input streng.
- Voeg checks toe tegen gevaarlijke strings/payloads, maar doe dit correct: whitelist/allowlist-validatie waar mogelijk, escaping/encoding waar nodig, prepared statements voor databasequeries, veilige bestandsverwerking en MIME/type-controle.
- Gebruik CSRF-bescherming indien relevant voor de gekozen architectuur.
- Voeg rate limiting toe op submit endpoints.
- Voeg veilige HTTP headers toe.
- Zorg dat foutmeldingen veilig zijn en geen gevoelige info lekken.
- Log veilig en zonder secrets.

Bestandsuploads:
- Max 2 MB.
- Controle op MIME type én extensie.
- Hernoem bestanden veilig op de server.
- Sla uploads op in een veilige mapstructuur op.
- Vermijd uitvoerbare bestandstypes.
- Toon hoe je misbruik voorkomt.
- Maak duidelijk welke bestandsformaten wel/niet toegelaten zijn.

Database:
- Lees connectiegegevens uit .env.local.
- Gebruik migrations of een duidelijk schema.
- Voorzie minstens:
  - submissions tabel
  - uploaded files tabel of equivalent
  - timestamps
  - statusvelden indien nuttig
- Gebruik veilige database access patterns.
- Maak geen aannames over de database zonder controle; detecteer of beschrijf hoe de app ermee omgaat.

Email:
- Gebruik SMTP-configuratie uit .env.local.
- Verstuur minstens een basis notificatie-email bij succesvolle submit.
- Maak mail templates eenvoudig maar proper.
- Zorg voor foutafhandeling als SMTP tijdelijk faalt.

Export:
- Voorzie export van submissions.
- Minstens CSV, XML.
- Indien passend ook XLSX.
- Denk aan filtering op datum/status indien haalbaar.
- Exports moeten veilig zijn en geen onnodige gevoelige data lekken.
